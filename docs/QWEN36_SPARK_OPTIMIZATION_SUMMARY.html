结论

30 tok/s 的短输出目标通过 ds4-server --qwen-compat-server 达成。 这条路径从 ds4-server 入口启动，并使用 Qwen 内置 MTP/NextN speculative decoding。

部署命令

服务入口保持为 ds4-server，MTP draft 深度默认 4，并关闭 reasoning 以避免吞吐测试被思考内容污染。

./ds4-server \
  --qwen-compat-server \
  -m "$HOME/models/Qwen3.6-27B-MTP-GGUF/Qwen3.6-27B-UD-Q2_K_XL.gguf" \
  --cuda \
  --ctx 2048 \
  --host 0.0.0.0 \
  --port 8000 \
  --mtp-draft 4

内部高性能运行参数：

-ngl -1 -fa on -np 1 --reasoning off --metrics \
--spec-type draft-mtp --spec-draft-n-max 4

已经落地的 ds4 改动

CUDA 量化覆盖

补齐 UD-Q2_K_XL 所需的 Q2_K、Q4_K、IQ3_XXS、IQ2_S、IQ3_S、IQ4_XS、IQ2_XS。

resident scaffolding

把 Qwen hidden、GDN state、full-attention KV、FFN、logits 和 sampler workspace 尽量留在 CUDA 侧。

服务兼容模式

新增 --qwen-compat-server 和 DS4_QWEN_COMPAT_SERVER=1，让 ds4-server 能调用成熟 MTP verifier。

Profiling 发现

native CUDA resident 大约 9.7 tok/s，主要时间耗在量化 GEMV 风格 matvec，而不是最终采样。

Kernel familyProfile 占比解释
matmul_q2_k_warp8_kernel约 22.5%FFN gate/up 压力最大
matmul_q3_k_striped2_kernel约 16.3%FFN down 和 attention projection
matmul_iq3_xxs_warp8_kernel约 11.8%GDN 和投影工作
matmul_q4_k_warp8_kernel约 9.9%混合 Qwen projection
matmul_iq2_s_warp8_kernel约 9.1%dense FFN 格式
matmul_q5_k_warp8_kernel约 8.5%GDN output/projection
matmul_q6_k_warp8_kernel约 6.8%output/logits head
结论：GPU argmax、top-only logits read 只能清理尾部开销，不能带来 3 倍加速。真正瓶颈是 Qwen 的量化 matvec schedule 和 Gated DeltaNet decode。

实测无效或负收益实验

实验结果

MTP 深度取舍

MTP 能把短输出推过 30 tok/s，但收益依赖 draft acceptance。深度越高不一定越快。
